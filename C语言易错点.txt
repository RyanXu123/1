【第一部分】我自己踩过的坑
----------------------------------------

1. printf 放错地方 —— 把"过程"当成了"结果"
   任务 2 求和，我把 printf 写进了 for 的花括号里面，
   结果打了 4 行：1 / 3 / 103 / 153。
   改法：printf 要放在循环的大括号外面，只打最后一行 153。
   两种都不算错，区别是"边加边看"和"加完再看"。

2. 分不清 printf 该在 if 里面还是外面
   找最大值那题，我把同一个 printf 放了三个位置试：

     for 外面          → 100             （最终答案）
     for 里、if 外     → 2 / 100 / 100   （每圈报到）
     if 里面           → 2 / 100         （只在换人那一刻报）

   记住：printf 在谁的花括号里，就跟着谁执行几次。

3. 罐子没声明就直接用
   写 count++ 之前忘了写 int count = 0;
   编译器原话：error: 'count' was not declared in this scope
   意思就是：count 是谁？我不认识。

4. 把动作塞进 printf
   我写的是 printf("%d\n", count++);
   能编译，也不报错，但那个 ++ 不干活、是多余的。
   数数要在 if 的花括号里数（count++;），报数在循环外面报。

5. if 的花括号空着，不知道该往里写什么
   任务 4 我只写了 if(b[i]>30){ } 就停住了。
   括号里要写"条件成立时该发生的事"：count++;

6. i 从 1 开始 —— 跟打擂台学的，但用错了地方
   找最大值从 i=1 开始，是因为第 0 个已经站在擂台上了。
   数个数没有擂主，每个位置都要点名，必须从 i=0 开始。
   验证：把数组第一个数改成 999，i 从 1 起还是只数出 2 个——
   漏了一个，程序还不报错。

7. 数组里塞字符（今天的报错）
   我写 int b[4]={"英语1","shuxue2",...};
   报错：invalid conversion from 'const char*' to 'int'
   int 的盒子只能装数字；字符串是另一路东西（以后学 %s）。

8. 旧账还没清
   - 2.cpp 里写的 printf("ok/n") —— 要写 \n 才换行，/n 会原样打印出来。
   - 6.cpp 缺 #include <cstdio> 和 int main()。


【第二部分】数组 + 循环的通用易错点
----------------------------------------

1. 下标从 0 开始
   int b[4] = {1,2,100,50};
   能用的下标是 0、1、2、3（不是 1、2、3、4）。

2. i <= 会越界
   for(int i=0; i<4; i++) 才是刚好四圈。
   写成 i<=4 会去读不存在的 b[4]。
   实测：int b[5]={1,2,3,4,5}; 用 i<=5 跑，最后一个打出 0——
   那个 0 不是数组里的数，是内存里的垃圾值。
   C 不会拦你，这才最危险。

3. 每个罐子的起点不一样
   求和 sum      → 从 0 开始（空罐子）
   数个数 count  → 从 0 开始（一个都还没数到）
   找最大 max    → 从 b[0] 开始（第一个先上台当擂主）

4. 初始化时给不满没事，给多了报错
   int b[4] = {1,2};       合法，剩下两个自动是 0 → 1 2 0 0
   int b[4] = {1,2,3,4,5}; 元素给多了，报错

5. 数组不能整体重新赋值
   int a[5] = {1,2,3};     声明时可以一次给
   a = {4,5,6};            不行！必须一个一个来：a[0]=4; a[1]=5;

6. 报内容要写位置，不写死数字
   想打印"哪几个数大于 30"，写 printf("%d\n", b[i]);
   不要写死 printf("%d\n", 100);
   想挤在一行：把 "%d\n" 改成 "%d "（换行符换成空格）。

7. printf 的格式串和参数要对得上
   %d 是给 int 留的空位，后面的参数按顺序填进去。
   少给一个，它会拽出一个垃圾值。

8. \n 不是 /n
   反斜杠是回车键上面那个键。


【第三部分】一句话总纲
----------------------------------------

花括号管两件事：执行几次、活多久。

  - 变量在花括号里出生，出了花括号就死。
  - 语句在谁的花括号里，就跟着谁执行。

今天四道题，一个零件都没多：
  += 是第 04 讲学的（累加器）
  ++ 是 for 第三格里的写法
  if 是第 02 讲学的

零件就那么几个。难的是想清楚：这一圈该干什么、干完放哪儿。

【第一部分】我自己踩过的坑
----------------------------------------

9. 函数不能套娃
   我把 int main(){...} 写进了 sayfor(){...} 的肚子里。
   报错：error: a function-definition is not allowed here before '{' token
   规矩：函数之间是**平级**的，一个挨一个站着，谁都不许住在谁肚子里。

10. 要执行的语句不能摆在文件最外层
   我把 sayfor(2); 写在了所有函数的外面。
   报错：error: expected constructor, destructor, or type conversion before '(' token
   规矩：最外层只放"定义"（#include、各种函数）。
         要执行的语句，必须写在某个函数的花括号里。

11. 程序从哪开始跑
   必须有一个 main，而且只能有一个。
   别的函数都是"待机的机器"，被喊到才动。
   被调用的函数要写在 main 的上面（编译器从上往下读）。

12. 少了函数名，括号就变成"逗号表达式"（今晚最阴的一个）
   我写：int s=(3,5);   心里想的是 int s=add(3,5);
   结果 s 不是 8，是 5！因为 (3,5) 是逗号表达式：
     从左往右算，最后一个的值留下来 —— 先算 3（丢掉），再算 5，值就是 5。
   同理 (9,1) 的值是 1。所以整个程序最后打印的是 6，不是 18。
   编译器**不报错**，只给一句 warning：
     warning: left operand of comma operator has no effect
   判断是不是函数调用，看**括号前面有没有名字**。有名字才是喊机器。

13. 变量不要写在大街上
   我把 int s = ...; 写在了所有函数外面（那就是全局变量）。
   C++ 能编过，纯 C 直接报：error: initializer element is not constant
   规矩：能用局部的，就别用全局。
   变量写在"要用它的那行上面"，而且要跟用它的语句在**同一个花括号**里。

【第二部分】函数这件事的通用易错点
----------------------------------------

14. 函数的四个零件，从上往下看
    void  add  (int a, int b)  { ... return a+b; }
    └不交货 └名字 └进料口（参数）  └身体      └交货+立刻下班

15. 返回值和打印不是一回事
    int add(...) { return a+b; }   → 交出来的值能接着用：
                                     int s = add(3,5);  printf("%d", add(s,100));
    void add(...) { printf(...); } → 只在屏幕上出现一下，拿不走。
    "外面有没有人要这个结果？有人要 → 写清楚类型；没人要 → void。"

16. 参数是复制进去的
    blinkFor(3) 里的 3，被复制给定义里的 times。
    函数里改 times，外面那个 3 一点事没有。
    参数真正的用处：让"每次不一样的那个数"变成可以换的东西。

17. 打一行 n 个星号（line 那题）
    循环里写 printf("*")  —— 里面**不要**带 \n
    换行那句 printf("\n") 放在循环的**花括号外面**
    要是 \n 跟着星号走，就变成竖着一列了。

18. printf("\n") 到底在干什么（吾辈以为它没用，其实是我只喊了一次）
    \n 是一个**看不见的字符**（编码 10 号），不是"反斜杠 + n 两个符号"。
    它的意思只有一件事：**光标跳到下一行开头**。

    为什么我觉得"加不加都一样"？
    因为我只喊了一次 line(5)。印完 ***** 后面就没人接着印了，
    空荡荡的看不出区别。**少了它不会报错，只会在某个没注意的场合露馅。**

    实测（两台机器各喊两次）：

      不带换行：
        lineA(5); lineA(3);
        输出 ********          ← 5 个和 3 个挤成一行，变成 8 个

      带换行：
        lineB(5); lineB(3);
        输出 *****
             ***             ← 各自一行

    想让它现原形：在后面随便加一句打印
        line(5);
        printf("===\n");
      把 \n 删掉，=== 会贴上去变成 *****===

    一句话：printf("\n") 不是"让这行好看"，
    是**告诉后面来的人：这条线画完了，下一个从新的一行开始。**

    顺带：2.cpp 里那个 /n 就是把这个字符写错了 —— 反斜杠写成斜杠，
    于是它变成真的一个斜杠加一个 n，直接印出来给你看。

【第三部分】一句话总纲
----------------------------------------

函数 = 一段代码 + 一个名字。

四个零件记牢：
  void      不交货
  (参数)    进门的东西，外面递进来
  return    交货 + 立刻下班
  main      唯一的开工地点；别的函数都在待机

摆位置的口诀：**外层排机器，main 里开工。**

【第一部分】我自己踩过的坑
----------------------------------------

19. printf 的 %d 忘了喂东西
    我写 printf("%d\n");  —— %d 是个洞，后面必须跟一个要填进去的值。
    没给，编译器最多给一句 warning 就放过去，运行时它会从内存里随便抓一个数塞进去，
    于是屏幕上蹦出 1729560576、0、-1、-3 这种鬼数字。
    规矩：**%d 有几个，后面就得跟几个对应的值。**

20. a[3] 不是"数组 a"，是"第 3 格"（今天第 2 次踩数组越界的兄弟）
    int a[3]={2,3,4};   能用的下标只有 0、1、2。
    我写 a[3]=a[3]-i; 程序不报错，输出 0 / -1 / -3。
    那个 a[3] 是隔壁内存，我还一直在改它。
    我要的效果（2 2 2）其实是对的，只要把 a[3] 改成 a[i]。
    判断口诀：**想让每一圈碰不同的格子 → 写 i；不想 → 写死数字。**

21. 花括号可以省，但只能省一句
    for (int i = 0; i < 3; i++) printf("%d ", b[i]);   ← 合法，只有这一句在循环里
    for (int i = 0; i < 3; i++)
        printf("A\n");
        printf("B\n");      ← 危险！B 不在循环里，只执行一次
    缩进骗人，花括号不骗人。if / for / while 都是这个规则。
    现阶段一律带花括号，要加第二句时才不用回头补。

22. "累加"碰到没初始化的数组 = 读垃圾
    a[i] = a[i] + 1;      累加，得先看原来的值
    a[i] = i + 1;         设定，直接盖上去，原来装什么都不看

    实测（数组故意不给初始值）：
      设定版  1 2 3 4 5 6
      累加版  1 1 1 2 2021653905 3     ← 里面全是内存垃圾

    想让每格变成"编号+1"  → a[i] = i + 1;
    想让每个数都加 1      → a[i] = a[i] + 1; （简写 a[i]++; 或 a[i] += 1;）


【第二部分】作用域与函数传参的通用易错点
----------------------------------------

23. 花括号是一间房，变量只在房间里活着
    int f(int a) { int b = a + 1; return b; }
    b 只在 f 的房间里。在 main 里写 printf("%d", b); 编译直接报：
      error: 'b' was not declared in this scope
    这不是编译器小气 —— f 跑完，房间就拆了，盒子跟着没。

24. 内层能看外层，外层看不见内层（遮蔽）
    int k = 1;
    {  int k = 2;
       {  int k = 3;  printf("%d\n", k);  }   → 3
       printf("%d\n", k);                     → 2
    }
    printf("%d\n", k);                        → 1
    里层的同名盒子把外层的"挡住"，不是改掉。实践上：**别用同名。**

25. 普通参数是复印件，数组是门牌号（第 07 讲唯一的例外）
    void half(int a)       { a = a/2; }   → 里面 50，外面还是 100
    void halveAll(int a[], int n) { ... } → 里面改了，外面真的变
    想改普通变量：必须 return 出来，外面自己接：
      m = half2(m);

26. 传数组必须给两个东西：名字 + 长度
    halveAll(b, 3);      对
    halveAll(b);         错，函数不知道多长
    halveAll(b[3], 3);   错，b[3] 是"第 3 格里的数"，不是那排盒子
    记住：**b 和 b[3] 完全是两个东西。**

27. sizeof 算长度的招，只在声明它的那个函数里管用
    main 里：int n = sizeof(a)/sizeof(a[0]);   → 6，管用
    函数里：int n = sizeof(a)/sizeof(a[0]);   → 1，失效
    因为函数里的 int a[] 已经变成门牌号了。**长度老实当参数传。**

28. 参数列表 = 类型 + 名字，位置对位置
    void halveAll(int a[], int n)
    //            第1格：一排整数   第2格：一个整数，告诉你多长
    括号里写的是"要什么"，不是"给什么"；给的东西在调用那一行。
    名字是里面随便起的：外面叫 b，里面叫 a，同一个门牌号两个称呼。

29. 全局变量是雷
    写在所有函数外面的变量，谁都能看见、谁都能改。
    出 bug 时你不知道是哪一处改的；起名还容易撞。
    **变量宁可多传一个参数，也别放全局。**
    （数组、普通变量都写在 main 的花括号里。）

30. main 也是函数
    int main(){...} 和 void sayfor(int times){...} 是同一种东西，
    只是操作系统开机后第一个喊的就是它。
    所以第 06 讲那个 int s = add(3,5); 写在所有函数外面 → 换个编译器就炸。
    正确位置：main 的花括号里。


【第三部分】一句话总纲（第 07/08 讲）
----------------------------------------

花括号管两件事：**谁能看见、改的是原件还是复印件。**

  - 变量在花括号里出生，出了花括号就死 → 作用域
  - 普通变量传进去是复印件，数组传进去是门牌号 → 一个改不动，一个改得动
  - 传数组永远两样东西：名字 + 长度

三个实验的输出（2026-09-20 实测）：
  11
  inside 50
  outside 100      ← 复印件的证明
  k3=3 / k2=2 / k1=1

【第一部分】我自己踩过的坑
----------------------------------------

31. 中文文件名把 exe 变成了乱码
    文件叫“第09讲字符串演示.cpp”时，编译出来的 exe 名字是乱码，
    任务再去找“正常名字”的那个文件，就报：
      不是内部或外部命令，也不是可运行的程序
    原因：g++ 在 Windows 上写非 ASCII 文件名会走 ANSI 代码页，名字对不上。
    改法：源文件用英文名（s09_string.c、p10_min.c）；编译任务固定输出 out.exe。

32. 终端显示乱码——程序其实没错
    输出是 UTF-8，终端按 GBK 读，中文全成了“鏁翠覆锛歨ello”这种。
    改法：编译任务里加 chcp 65001；程序里也可以 SetConsoleOutputCP(65001);
    记住：看到乱码先怀疑编码，别先怀疑自己的逻辑。

33. 倒着印字符串，把 n-1 写成了 n
    s[5] 是 \0，印出来是一片空白，所以肉眼看着“结果没变”。
    其实多跑了一圈。想看见它，把 %c 换成 %d，最前面会多出一个 0。
    眼睛看不见的东西，不等于没发生。

34. 指针第一次上手，四个错一起犯
    - include <stdio.h> 少了 #
    - void swap(int *a int *b) 参数之间少逗号
    - t = *b; 写反了，应该是 *b = t;
    - swap(&a,&b) 名字用错，main 里只有 x 和 y
    编译器原话：
      error: expected ';', ',' or ')' before 'int'
      error: 'a' undeclared (first use in this function)

35. 用 %d 去印 &x（把门牌号当值用）
    编译器警告：
      warning: format '%d' expects argument of type 'int',
               but argument 2 has type 'int *'
    跑出来是 1476393788 这种数字——地址被硬当整数读出来的半截。
    规矩：printf 要值（不写 &），scanf 要门牌号（必须写 &）。

36. “程序能跑”不等于“题目做完了”
    求和那题我写了读两个数、打印两个数，编译零警告，
    但题目要的是“和”——少了加法那一步。
    分号少一个，编译器会骂你；漏做题目要求，它一声不吭。
    交卷前对着题面再念一遍：它到底要我输出什么。


【第二部分】第 09~11 讲的知识点
----------------------------------------

37. 字符串 = 一排 char + 末尾的 \0
    char s[6] = "hello";   →  h e l l o \0
    五个字母要开六格。\0 是编号 0 的隐形字符，
    printf("%s") 一路读到它才停手。

38. 两个格式符分工
    %c 印一格（写 s[0]）；%s 印整串（写 s，不写 s[]）
    'a' 是一个字符，占一格；"a" 是一串，占两格（含 \0）。

39. 指针的三张面孔
    &x             取门牌号（问：x 住哪）
    int *p = &x;   声明：p 是专门装门牌号的盒子
    *p             动作：顺着门牌号取内容
    口诀：声明时的 * 是名片，使用时的 * 是动作。

40. 等号左右的 * 分工不同
    t = *b;   读：把 b 盒子里的值抄出来
    *b = t;   写：把 t 的值写进 b 那个盒子
    左边带 * 是往里写，右边带 * 是从里读。

41. swap 模板（背下来）
    void swap(int *a, int *b) {
        int t = *a;
        *a = *b;
        *b = t;
    }
    调用：swap(&x, &y);   ← 这个 & 不能省
    少了它，函数收到的是复印件，外面一点不动。

42. 为什么普通参数改不了外面、数组能改
    普通参数进函数是复印件；数组名是第一格的门牌号。
    函数头写 int a[]，本质就是 int *a。
    推论：函数里 sizeof(a) 失效，长度必须另外当参数传进来。

43. scanf 的规矩
    读整数：      scanf("%d", &n);
    读数组元素：  scanf("%d", &a[i]);
    读整个字符串：scanf("%s", s);    ← 这里不写 &
    几个 %d，就对应几个 &；scanf 要的是盒子在哪，不是盒子里的值。

44. printf 不自动换行
    光标停在原地，后面的输出接着往后写，
    所以要手动 printf("\n") 把光标送回下一行开头。

45. 拆题三步（综合题没思路时就靠这个）
    ① 输入是什么形状（一个数？一排数？一串字符？）
    ② 输出是什么形状（一个数？两个数？一行一行？）
    ③ 中间要记哪几个罐子（max、pos、count、sum……）
    三步用中文写不出来，代码就先别写。


【第三部分】一句话总纲（第 09~11 讲）
----------------------------------------

值 和 门牌号 是两种东西。
  printf 要值；scanf 要门牌号；函数想改外面的变量，也要门牌号。
  数组名本身就是门牌号——所以递它不用 &，sizeof 也失效。

字符串就是：一排 char，末尾挂一个 \0。


【第四部分】位运算 · 符号速查（2026-09-26 补）
----------------------------------------

46. 五个符号，一张表
    &   按位与     两位都是 1 才是 1        6 & 3 = 2
    |   按位或     有一位是 1 就是 1        6 | 3 = 7
    ^   按位异或   两位不一样才是 1         6 ^ 3 = 5
    ~   按位取反   0 变 1、1 变 0（只对一个数用）
    <<  左移       整体往左挪，右边补 0；<< 1 等于乘 2
    >>  右移       整体往右挪，右边丢掉；>> 1 等于除以 2

47. 位号从右边数起，最右边是第 0 位
        位3  位2  位1  位0
    权重  8    4    2    1      ← 就是 2 的 n 次方
    45 = 101101 → 位0=1、位1=0、位2=1、位3=1、位4=0、位5=1
    第 0 位决定奇偶：是 1 就是奇数，是 0 就是偶数。

48. 钥匙 1 << n
    1 << 0 = 1     00000001
    1 << 1 = 2     00000010
    1 << 2 = 4     00000100
    1 << 3 = 8     00001000
    它只有第 n 位是 1、别的位全是 0。1 只有一颗，左移就是把它往左推。

49. 拿到钥匙以后的四招（num 是原数，n 是位号）
    置 1：      num | (1 << n)
    清 0：      num & ~(1 << n)
    翻面：      num ^ (1 << n)
    读这一位：  (num >> n) & 1        ← 只报数，不改原数
    注意：num & (1 << n) 给的不是 0/1，而是 0 或 1 << n。

50. 这次踩过的坑（2026-09-26）
    ① 位号方向搞反：以为最左边是第 0 位。
       （45 从左边数第二位是位 4，那是 0；从右边数第 2 位是 1。）
    ② 以为 a >> n 就是"第 n 位"：它是"从第 n 位往上一整段"，
       85 >> 1 = 42，不是 0 或 1。要那一位，得再 & 1。
    ③ 想"移出去改完再移回来"：移回来的时候低位那串会一起移上去，
       还得补一次掩码清掉，越写越绕。直接用钥匙对原数动手最省。
    ④ 打印被啃光的数：循环里 n = n >> 1 把原值吃到 0，
       要进循环前先留一份（int reg = n;），打印 reg。
    ⑤ 大小写不一致：变量叫 N，函数里写 n——编译器当两个东西。
    ⑥ 函数写在 main 下面又不写原型：gcc 报
       error: implicit declaration of function 'set_bit'。
       写在 main 上面就不用原型；写在下面就得在 main 前补声明。
    ⑦ 参数是复印件：函数里改 num，外面的数一点没动（第 07 讲那三个实验），
       所以四个函数都得 return 回去。

51. 题九那四个函数（写不出来时再对照）
    set_bit(num, n)     → return num | (1 << n);
    clear_bit(num, n)   → return num & ~(1 << n);
    toggle_bit(num, n)  → return num ^ (1 << n);
    get_bit(num, n)     → return (num >> n) & 1;
    参考代码：cpp-demo\_teacher\answer\ex09_bit_ops.c


【第五部分】综合题 · 题三水仙花数踩坑（2026-09-27 补）
----------------------------------------

52. 拆一个数的每一位（通用骨架）
    int t = n;              替身，拿去拆；n 留着不动
    int sum = 0;
    while (t != 0) {
        int d = t % 10;     拿最后一位
        sum = sum + d*d*d;  用掉这一位
        t = t / 10;         削掉这一位
    }
    三个动作的顺序不能换：先拿、再用、最后削。
    削必须放末尾，因为下一圈的"最后一位"是从削短之后的数身上拿的。

53. 原值待会儿还要用，就不能拿去当消耗品
    拆位会把数一路削成 0。要拿它比大小（sum == n），
    就得在进循环之前先留一份（int t = n;）。
    直接拿 n 去拆：拆完 n 是 0，比的是 153 和 0，永远为假。
    实测：不留副本，1~1000 里一个水仙花数都挑不出来。

54. 别拿循环的"上界"去拆
    n 是题目给的边界，被拆成 0 之后 for 的条件 i <= n 当场垮掉，
    跑两圈就退出来了。要考察的数永远是循环变量 i 自己。

55. 变量只在它出生的那对大括号里活着（作用域）
    在 panduan 里写 int count = 0; 回到 main 里喊 count →
    error: 'count' undeclared
    函数一结束，里面的 count 就跟着没了；编译器还会顺口提醒
    set but not used。要在 main 里记数，就在 main 里声明。

56. 单等号是赋值，双等号才是比较
    if (count = 0) 是把 0 塞进 count，然后判断 0（假），永远不成立。
    该写 if (count == 0)。
    这个错编译器不报，只会安静地错给你看。

57. 循环外面的事，别写进循环里
    "一个都没打到过就打印 0"这句必须放在 for 结束之后。
    写在 for 里面 → 输入 0 时循环一圈都不跑，这句也轮不上。
    症状就是：输入 0，屏幕上什么都没有。

58. 调用函数只写值，不写类型
    错：panduan(int sum, int n)
    对：panduan(i)
    报错：error: expected expression before 'int'
    类型只有"定义"函数的时候才写。

59. 判断函数该自己干活
    收一个数 → 自己在里面拆、自己比 → 返回 1 或 0。
    把拆位留在 main 里，函数就空了，等于白写。
    顺带一层保护：函数拿到的是复印件，里面怎么拆都伤不到 main 的 i。

60. for 的边界别顺手写小于
    题目说"N 以内" → i <= n。
    写 i < n 会把 N 本身漏掉。

61. 少一个分号，编译器会指着下一行骂
    int e=(n/10) 末尾少分号 → error: expected ',' or ';' before 'int'
    它报的位置是下一行，因为它在等上一句结束。
    看到 expected ... before 'int'，先回头查上面那行的末尾。

63. int 也有装不下的时候（阶乘翻车）
    int 最大约 21 亿 4748 万。12 的阶乘 4 亿多，刚好塞得下；
    13 的阶乘 62 亿，一出门就撑破，从那以后打印的全是乱码。
    实测递归阶乘：输入 13 → 1932053504（真值 6227020800）、输入 20 → 负数、
    输入 9178 → 0（乘得太久，低 32 位全被抹成 0 了）。
    症状：算得越大越离谱、甚至变负数或 0——不是写法错，是装不下。
    题四验收只给 5 这类小数字，所以先不用换类型；知道有这回事就行。

64. 改外面的变量，得递门牌号（传值 vs 传地址）
    void swap_wrong(int a, int b)：换的是两份复印件，外面 x、y 一点没动
        → 值版过后：x = 1, y = 2
    void swap_right(int *a, int *b)：收地址，进去直接改屋里
        → 指针版过后：x = 2, y = 1
    调用也要跟着改：swap_right(&x, &y)，&x 就是"x 的门牌号"。
    跟 scanf("%d", &n) 是同一个道理——要能改到外面的变量，就得把地址给它。
    例：cpp-demo\_teacher\_tmp\p26_swap_demo.c

65. 取余 % 的边界：% n 给的是 0 ~ n-1，给不出 n
    rand() % 10   → 0~9，永远拿不到 10
    rand() % 900  → 0~899，加上 100 才是 100~999（最大值 999，不是 900）
    2026-09-29 口答连错两题，错的是同一个点：把 % 的右边界当成了 n。
    记法：% 就是"剩下的零头"，除以 n 的余数最大只能是 n-1。
    想要 lo~hi：rand() % (hi - lo + 1) + lo

66. 函数括号里的名字，是当场声明出来的变量
    void swap(int *a, int *b)：a、b 不是"填空提示"，是真的变量名，
    就在这一行声明出来的，函数身子里就靠这两个名字干活。
    拆开读 int *a：int 是类型，* 表示"这是装地址的盒子"，a 是名字。
    跟 int a; 是同一个模板，只是类型从 int 换成了"指向 int 的指针"。
    ① 名字随你起：改成 (int *left, int *right) 照跑（实测 x、y 换成 2、1）。
    ② 但声明和身子必须同名：声明写 left/right、身子写 a/b →
       error: 'a' undeclared。参数名只属于这个函数自己。
    ③ 外面叫 x、y 也没关系——函数里那对盒子是新的，只是被塞进了地址。
    所以括号告诉你的其实是"个数 + 类型"：两个，都得是地址，
    调用才写成 swap(&x, &y)。名字是给函数自己用的，跟调用方无关。
    例：cpp-demo\_teacher\_tmp\p30_param_names.c、p30_name_mismatch.c

67. 算了不等于改了：x / 10; 这行等于没写
    gcc 会报 warning: statement with no effect —— "这句算了，可没人接住"。
    实测：写完 r / 10;  之后 r 还是 456；写成 r = r / 10; 才变成 45。
    放进 while 里后果最狠：拆位循环里的 r 永远不变 → 死循环停不下来，
    计数器一路涨过数组边界（实测限制到 25 圈都没停，o 已经 25，而数组只有 20 格）。
    记法：想让一个值变小，左边必须有 = 或者 ++ / --。
    2026-09-30 题二第一版栽的就是这个，而且同一行写错了两处。

68. 方括号里必须写"第几格"
    printf("%d", box[]); → error: expected expression before ']' token
    编译器不知道要哪一格。要一位一位打出来，用循环：
    for (int i = 0; i < o; i++) printf("%d", box[i]);

69. 计数器 o 站在"下一个空位"，不是"最后一格"
    拆位循环结束时，o 等于"一共装了几个"，最后一格是 o - 1。
    写 box[o] 取到的是从没写过的那一格——里面是残留的内存，不是 0、也不是数组里的数。
    实测（题二第二版，输入 123）：打印出 941954541，而且每次跑都一样，
    最容易让人以为那是个"算出来的结果"。
    正确写法：for (int i = 0; i < o; i++) printf("%d", box[i]);
    这也是第 05 讲那条规矩的另一面：int a[5]; 不给值的时候，里面就是垃圾。

70. 打印整个数组要用 for 循环，数组名本身不是值
    对：for (int i = 0; i < o; i++) printf("%d", a[i]);
    错：printf("%d", a);  → warning: format '%d' expects argument of type 'int',
        but argument 2 has type 'int *'；实测打出来的是 -398460464 这种地址数。
    两个细节：
    ① 循环的上界写"实际装了几个"（o），别写数组声明的大小（20）——
       后面那些格子没写过，会打出 68 条那种垃圾。
    ② 想封成函数就写 void print_all(int a[], int n)，数组当参数要连个数一起传
       （第 08 讲）。例：cpp-demo\_teacher\demo\p34_print_array.c

71. （第 57 条的复发）2026-09-30 题二：这回是 for 的大括号站错了层
    第 57 条那个毛病从 if 换成了 for 的大括号：
    打印的 for 被留在了外层"轮"循环里面，于是每轮结束都打一遍数组，
    五轮五串糊成一行：904321043219032149021349012349012349。
    看着像乱码，其实结果是好的（最后一串 012349 就是答案）。
    判据：问一句"这句想跑几次？" 想跑一次 → 写在两层循环外面。

72. 别凭"输出糊成一坨"就判程序错了——先数位数，再看顺序
    2026-09-30 题二第四版：程序其实是对的（701321 排前、011237 排后），
    主人说"还是不对"，原因是两句 printf 中间没有换行也没标签，
    两串数字粘成 701321011237，看着像一个十二位数。
    判断步骤：
    ① 数位数：随机数三位 + 学号位数 = 总位数；排前后两段必须一样长。
    ② 看顺序：后半段是不是一格不比一格小（相等也算对）。
    ③ 输出要给人看：加 \n、加标签（"排之前："／"排之后："）。
    交付给学长的版本只留结果那一串就够了（题面例子就是输出 123456）。
    【2026-09-30 第三次】第 57 条的判据又用了一遍：\n 和"之前:"都写进了循环里，
    于是每一位前面贴一个标签、每一位后面换一次行。
    \n 不是段落符，是"打到这里就换行"，跟着每一次 printf 走。
    要连成一串：标签单独打一次、\n 单独打一次，两者都放循环外面，循环里只打数字。

73. switch 里要声明变量，当场给它套花括号 { }
    为什么：case 只是标签，几支共用一个作用域。在 case 1 里写 int y = 10; 然后 case 2 里用 y，
    case 1 那行根本没执行过 —— y 是个空盒子。
    实测（cpp-demo\_teacher\_tmp\sw_skip_init.c）：
      gcc -Wall -Wextra 只给一句 warning: 'y' is used uninitialized，实跑 r = 0（运气好）；
      g++ 直接 error: jump to case label / crosses initialization of 'int y'。
      "只警告不报错"的最难查 —— 它编得过、跑得动，结果就是错的。
    修法：case 1: { int y = 10; ... break; }   每支各自圈起来。
    实测对照 sw_brace_ok.c：gcc 和 g++ 双双零警告，r = 20。
    （顺带纠正：case 标签后面直接写声明，C 里是合法的，不报错；那是 C++ 才拦。
      探针 sw_err_decl.c 编过、跑出 10。）

74. switch 只跳出最近那一层，不是跳出循环
    现象：switch 嵌在 for 里面，case 那一支 break 之后，外面的循环还在跑。
    实测（cpp-demo\_teacher\_demo\p31_switch_more.c 第 5 段）：三轮全跑完，
    每轮 switch 后面那行 printf 也都执行了。
    顺带两条 switch 的硬规矩：
      ① 括号里只能放整数（int / char / enum）。塞 double 报
         error: switch quantity not an integer。
      ② case 后面只能写编译期常量。case 20 + 1: 行（当场算成 21）；case c:（c 是变量）报
         case label does not reduce to an integer constant。
      ③ case 3 ... 5: 那种范围写法是 GCC 私货，加 -pedantic 就警告，别交给学长。

75. 参数写成枚举类型，C 不会替你把关
    现象：void print_speed(enum FanSpeed s) 这么写，调用时硬塞 print_speed(2)，
    gcc -Wall -Wextra 一声不吭（退出码 0，实跑打出 s = 2）；
    同一份文件用 g++ 编就直接 error: invalid conversion from 'int' to 'FanSpeed'。
    结论：C 里参数类型主要写给读代码的人看（"这儿只该交档位"），
    别指望编译器替你拦。C++ 才拦。
    探针：cpp-demo\_teacher\_tmp\sw_enum_arg.c

76. C 里写枚举变量，enum 那个词不能省
    现象：enum FanSpeed { LOW, MID, HIGH }; 之后写 void print_speed(FanSpeed s)，
    gcc 直接 error: unknown type name 'FanSpeed'（连带 main 里的调用也报 implicit declaration）。
    同一份文件用 g++ 编却过 —— C++ 把标签名也塞进普通名字里，C 不塞。
    规矩：C 里凡是提到这个类型，都要带 enum：enum FanSpeed s;  /  enum FanSpeed state = LOW;
    想省掉 enum 只有 typedef 一条路（还没上过课）。
    探针：cpp-demo\_teacher\_tmp\sw_nokw.c

    另：参数写 enum FanSpeed 还是 int，C 里跑起来一模一样
    （_tmp\sw_intarg.c：参数改成 int、case 照样写 LOW，零警告，print_speed(7) 也照收）。
    区别只在可读性和将来换 C++ 时的类型检查 —— 所以还是写 enum。


77. 想装"一串字"，盒子要开成一排：char n[100]，不是 char n
    现象：char n; scanf("%s",&n); printf("%s",n);  编出来一行 warning
    "format '%s' expects argument of type 'char *', but argument 2 has type 'int'"，
    跑起来直接崩（退出码 0xC0000005，访问冲突）。
    三处都错：char n 只有一格，装不下"一串"；&n 是"一格的门牌号"，%s 会往它后面倒一串；
    printf 那行把 char 当指针用。
    规矩：
      · 一格字符：char c;      scanf("%c", &c);   printf("%c", c);
      · 一串字符：char s[100]; scanf("%s", s);    printf("%s", s);   ← 前面不写 &
      · %s 配一排（scanf 会自动在末尾补 \0），%c 配一格；两者不能换用。
      · scanf("%s") 碰到空格就停，这是它本身的限制。
    探针：cpp-demo\_teacher\_tmp\bad_char.c（原样崩）、
          cpp-demo\_teacher\demo\p40_read_string.c（改好的，实跑 13 格）


78. %c 和 %s 不能串台：一个要"一格的心"，一个要"一排的门牌号"
    现象（主人写的两版都错，但错法不一样）：
      a) char n[20]; scanf("%c",n); printf("%c",n);
         gcc: warning "format '%c' expects argument of type 'int', but argument 2 has type 'char *'"。
         跑起来印一个乱码字符 —— %c 要的是那一格里装的值，n 给的是地址。
      b) char n[20]; scanf("%c",n); printf("%s",n);
         gcc 一声不吭（类型碰巧对），跑起来全看运气：本机只印出 h，主人机上一堆乱码。
         原因：n[0] 收了那一个字符，n[1] 往后是没初始化过的旧垃圾，中间没有 \0，
         %s 一路印到撞见 0 才停。这是未定义行为 —— 同一个 bug，不是每次错得一样。
    规矩：
      · 一格：char c;      scanf("%c", &c);   printf("%c", c);
      · 一排：char s[20];  scanf("%s", s);    printf("%s", s);
      · \0 是停车位：scanf("%s") 自动补，scanf("%c") 不补。
        所以用 %c 读过的数组里没有 \0，不能拿 %s 去印。
      · 记法：%c 要心（值），%s 要门牌号（地址）。变量前面带 &，数组名本身就是门牌号。
      · 局部数组没初始化就是垃圾；要清干净用第 05 讲那个 = {0}（char s[20] = {0}; 同理）。
    探针：cpp-demo\_teacher\_tmp\var_a.c、var_b.c、demo\p41_char_vs_string.c


79. 挑数字进 box：两个错挨在一起（存的是字符编号 + 印了 o 号那一格）
    现象：for 里的 if 判对了、count 也数对了（7），但
      a) box[o] = n[i];  存进去的是**编号**（'7' 是 55），不是数字 7；
         真印出来会是 55 54 49 51 52 53 57 这一串。
      b) printf("%d", box[o]);  o 是"已经挑出来几个"，也是"下一个空位"。
         循环结束时 o=7，可最后一个数字住在 box[6]，box[7] 从来没写过，
         里面是不确定的垃圾 —— 本机跑出 0，换台机器可能是别的数。
         改用 for(int i=0;i<o;i++) 才是一个不落。
    规矩：
      · 存：box[m] = c - '0';        （字符编号减 '0' 才是数字）
      · 印：for (int i = 0; i < m; i++)    能用到的最大下标是 m-1

80. 数组塞不进数、程序"不打印" —— 都是 scanf 那点事（2026-10-04）

  现象一：int box[20]; scanf("%d", box); 想一次读 20 个数。

    实跑（喂 1~20）：1 32759 1917720045 32759 -1179284672 602 0 ...
    原因：数组名 box 等于 &box[0]，那一行只往第 0 格放了一个数；

          错在逻辑不在类型 —— 没警告不代表对。
    规矩：格子写成 box[i]，scanf 里就写 &box[i]；只有整个数组名单独当"起点地址"用时才不带 &。

  现象二：读 n 个数的程序"一直不生成 print"。

      1) 它在等输入：n 要几个就得喂够几个，最后一个数也要按回车。光标停在原地 = 这种。
      2) n 填了 0 或负数：两层循环一次都不走，屏幕上只剩一个空行，看着像啥都没输出。
         实跑 n=0 → 只打出提示 + 空行，退出码 0。
      3) 数字不够、输入还被掐断（重定向文件读完 / Ctrl+Z）：scanf 读不到就不动那一格，

    另有一条 VS Code 专有：连提示行都没出现、任务像死了一样 → 上一只 exe 还挂在后台

    探针：cpp-demo\_teacher\_tmp\t_print_wait.c

  81. 去极值平均：题面那组数会把错的写法蒙对（2026-10-04）
    题面数据 {3,5,1,8,2,9,4,6,7,5}：正确答案 (50-9-1)/8 = 5.00；
    错写法 sum / n = 50 / 10 = 5.00 —— 一模一样，看不出错。
    原因：一组数里最大和最小"一上一下"互相抵消时，掐头去尾的平均值和全体平均值正好相等。
    换一组非均匀的验：{1,2,3,4,100} → 正版 (110-1-100)/3 = 3.00，错版 110/5 = 22.00。
    规矩：验算至少换一组"偏"的数据，别只拿题面那组；题目给的例子往往正好是特殊情形。
    参考实现在 cpp-demo\_teacher\answer\ti10_answer.c（零警告，两组都跑过）。
  82. 输入的顺序要跟 scanf 的顺序对得上（2026-10-04）

  83. 「读走」不抹数据，抹的是账（2026-10-07）
    现象：主人问"2 被读走了，数组里的 2 就空了？"——查输出，读完 1、2 之后 box=[1 2 3 4 5 -1 -1 -1] 一字未变。
    真因：读出来的是复印件（int data = box[head];），格子原封不动；C 不会替你把"读过的"删掉。
          "圈里还剩几个"全靠自己记账：head 往前挪一格（宣告这格出圈）+ count--（少了一个）。
          出圈那格里的旧值变成垃圾，等以后被 tail 绕回来盖掉。
    规矩：环形缓冲里"有没有数据"看的是 head/tail/count 三个数，不是格子里有没有值。
    亲缘：第 11 讲"scanf 要的是地址"讲的是数据怎么进去；这条讲的是数据怎么算出去。
  84. 满的时候 count-- 又 count++，不是白干（2026-10-07）
    满员还写：head 前进 + count--（请走最老的），写入 + count++（新来的坐下），净变化 0。
    抵消正是对的：挤掉一个、写进一个，数目不变、名单换了。不抵消的话 count 会涨到 9，比容量 8 还大。
    实跑：写 11 之后 box=[9 10 11 4 5 6 7 8]、head=3、tail=3、count=8。

  85. 不写 #include <string.h>，编译直接失败（2026-10-09）
    现象：调用 strlen / strcmp 却只 include 了 stdio.h → gcc 16.1.0 报
      error: implicit declaration of function 'strlen' [-Wimplicit-function-declaration]
      note: include '<string.h>' or provide a declaration of 'strlen'
    真因：编译器不认识这个名字。它得先知道"有这么个函数、要几个参数、返回什么"，才知道怎么排参数、怎么解释返回值。
    规矩：用谁家的工具，先借谁家的册子。stdio.h 管 printf / scanf，string.h 管 strlen / strcmp / strcpy / strcat / strncpy。
    探针：cpp-demo\_teacher\demo\err_p57_no_header.c（故意不写，编译退出码 1）

  86. 头文件是"目录册"，不是"库"（2026-10-09）
    三层：① 这些函数的真身住在系统库里，不在你的 .c 里；
          ② 头文件(.h)里装的是**声明**（说明书），告诉编译器"有这么个东西"；
          ③ #include 是**预处理指令**：编译之前把那个文件的内容**原样抄进**你这一行（是"抄进来"，不是"连上去"）。
    尖括号 < > = 去系统目录找；引号 " " = 先到自己这个文件夹找（以后 include 自己写的 .h 用这个）。
    另一条：**声明和链接是两回事**。头文件管"让编译器通过"；真代码在链接那步才接上。
    真见到 undefined reference to 'xxx'，那是链接阶段没找到库，别再回头怀疑头文件。

  87. strcmp 说"相等"的时候返回 0（2026-10-09）
    0 在 C 里一向当"假"用（if 就吃这一套），可这里 0 偏偏表示"一模一样"；返回值非 0 反而表示"不一样"。
    glibc 手册原话：string comparison functions return a nonzero value if the strings are **not** equivalent rather than if they are。
    规矩：判相等只能写 strcmp(a, b) == 0；写成 if (strcmp(a, b)) 意思正好翻过来。

  88. 字符串不能拿 == 比（2026-10-09）
    现象：char a[20] = "apple"; char c[20] = "apple"; 内容一样，if (a == c) 却说"不一样"。
    真因：数组名是门牌号（第 08 讲那条），== 比的是两个地址，不是格子里的字。
    而且 gcc 只给一条 warning（-Warray-compare），**程序照样跑、结果就是错的**。
    规矩：比内容用 strcmp(a, c) == 0。

  89. strcmp 的返回值只认"负 / 0 / 正"（2026-10-09）
    POSIX 原话：返回值 greater than, equal to, or less than 0。具体是多少不保证——
      glibc 手册的例子给的是"第一对不同字节的编号之差"（ABC vs AB → 67，ABA vs ABZ → -25）；
      本机 ucrt 给的是 1 / -1。
    两边都合法。规矩：只写 == 0、> 0、< 0，别背 -1、更别写 == -1。
    自己写比较函数也照"负 / 0 / 正"来定。

  90. strcmp 按字节编号比，不管字典序、不管大小写（2026-10-09）
    逐格比编号，第一处不同的地方定胜负；前面全同、其中一个先到头 → 短的排前面（"AB" < "ABC"）。
    大写（65~90）全在小写（97~122）前面 → strcmp("Zebra", "apple") 是负的，跟词典顺序相反。
    中文比的是那几个字节的编号，跟拼音没有半点关系。

  91. strlen 数的是字节，不是字数（2026-10-09）

  93. strcpy / strcat 的目标开不够 = 未定义行为（2026-10-09）

  102. myLen 差一个词：起点忘了给初值（2026-10-10）
    主人写的（hw_strlib.c 第一个函数）：
      int len;                                  ← 没给初值
      while (s[len] != '\0') { len = len + 1; }
      return len;
    编译器当场就喊了（-Wall）：
      warning: 'len' is used uninitialized [-Wuninitialized]
      note: 'len' was declared here
    实跑：len(a) = 13（要 5）。
    真因：len 里装的是栈上的垃圾值。这一次恰好是 13，而 char a[20] = "apple" 里第 6~19 格被自动补成 0
      （第 05 讲：= "..." 没写到的位置一律填 0），于是 s[13] 读到那个 0，循环一次都没走，直接把垃圾起点 13 返回了。
    换台机器、换个数组、或换个优化等级，它就会变成别的数，甚至越界读崩 —— 这就是"未定义行为"的日常长相。
    规矩（第 03 讲三要素里的"起点"）：凡是拿变量当下标或累加，写的时候就把初值落下。

      改后：int len = 0;
    改完实跑 len(a) = 5、零警告。逻辑没错（"数到 '\0' 之前"这一层是对的），丢的只是起点。

## 新库函数必须先查手册（2026-10-09 主人抓包之后定）

主人原话：「怎么这讲有点奇怪呢?参考参考文档和教程了吗?」

背景：第 24 讲（strlen / strcmp / strcpy）第一版是凭记忆 + 自家账本写的，漏了三处 ——
`strlen` 数的是字节不是字数、`strcmp` 的比较规则没写进正文、`strcpy` 的边界公式与 `strncpy` 的坑没提。
被问住之后回头查手册才补齐，示例也重跑过。**凭记忆写库函数这一条，以后不许再犯。**

规矩（开讲新库函数 / 新概念的课前走一遍）：

1. **先查权威手册**，再写讲义。Linux man-pages 本机可直连：
   `curl -sL https://man7.org/linux/man-pages/man3/<函数>.3.html`（2026-10-09 实测通）。
   cppreference 走 Cloudflare 拦截（返回 `Just a moment...` 那种挑战页），curl 抓不到，别白费劲；MS Learn 作备用。
2. **标准保证什么 / 这台机器给什么，分开写**。手册上的例子可能是别的 libc 的行为
   （glibc 的 `strcmp` 返回两格编号之差 67 / -25 / 7，我们 ucrt 上是 ±1）——两边都写出来，结论落在"标准只保证负 / 0 / 正"。
3. **讲完必须本机实跑复核**，把真实输出贴进讲义，不许只写"理论值"。
4. 边界条件（装不下、越界、不补终止符）要给出**手册原话**级别的说法（如"未定义行为"），不要用"可能会出错"糊过去。

主人原话：「`#include <string.h>` 你也没告诉我这个啊 `.md` 又不是没说让你解释不认识的?你为什么又不看 md?」

## 术语别混：同一个活的两套做法 ≠ 「两个版本」（2026-10-09 主人问「什么叫手写版,现成版,这两个版加一起不才是完整的代码吗」之后定）

本座写「手写版 vs 现成版」，主人听成了"两个版本的程序，得拼起来才完整"。
**「版本」这个词只用于同一份东西的前后改动**（改了注释/改了实现）；同一个活的两种做法，说「**自己写的一套 / 库里现成的一套**」。

配套两条：

1. 一份示例里同时摆两套（自写 + 库里）时，文件头**必须写明**：两套干的是同一个活，摆一起是为了对答案，不是拼起来才算完整。
2. 一个 C 程序只能有一个 `main`——凡"两份合起来"的说法都不成立，讲义里要点破这一层。

## 讲零件给片段、不给整份（2026-10-10 主人定）

主人原话：「不用再把完整实例贴出来，但是讲某个零件时还是要代码，而且他的前置得告诉我」。

1. **不再往对话里贴整份示例文件**——太长，主人看不完。完整件放 `demo\`，回复里只给**路径**，要他看再展开。
2. **讲零件必须给片段**：一次只摆一个零件（一个条件、一次自增、一个函数调用），片段用围栏标好。
3. **每段片段前面先写「前置」**：这段代码依赖哪一讲的东西、哪些变量/函数已经存在、怎么编译。
   例：「前置：`line` 是以 `'\0'` 结尾的 char 数组（09 讲）；`i` 是 int 下标（05 讲）」。
4. 涉及"为什么要写这一句"的，能跑对照就**跑一个对照件**并贴结果（退出码也算结果）。
## 查"讲过没有"要连语法结构一起查（2026-10-10 主人指着第 25 讲片段问「这些语法你是不是没讲过」之后定）

旧规矩只查"代码里的名字"（函数名、头文件、关键字），漏掉了**写法**。第 25 讲就栽在这儿：
`pHead + 1`、`pTail - pHead`、`if (p == NULL)` 这三处分别在用指针算术和空指针判断，第 10 讲压根没讲——
查名字查不出来（`pHead` 是新起的变量名），主人一眼就看出来了。

规矩改成两条：

1. 讲义发出前，把新片段里**每一种写法**过一遍：声明、赋值、比较、指针加减、类型转换、取值、函数调用的形态。

   补过的落成 `补充_XXX.md`，别塞在正文里糊过去。
